# C2 · captura de fuentes y resultado propio

Continúa el motor nuevo autorizado por Marcelo, desarrollado con datos sintéticos en este worktree. SQL123 y la API interna capturan fuentes propias verificadas y conservan una entrada y un resultado técnicos inmutables. Noelia necesita recuperar exactamente lo calculado, incluso después de cambiar los parámetros. Este incremento local todavía no cierra C2 ni acredita una liquidación municipal en producción.

El cliente sólo declara período, tipo, selección completa, ámbito, versión aprobada del programa y dominio `native_registered`. No puede suministrar personas, valores, reglas, resultados, sesión o autoridad. La API consulta membresía y permisos antes de leer el cuerpo. La base vuelve a comprobar la sesión, identidad vinculada, ámbito y capacidades. La lectura nominal y el cálculo son capacidades distintas de cargar novedades. SQL123 define tres capacidades nuevas y no las concede a ningún rol.

La selección admite contratos propios explícitos, convenios, reparticiones o todos los contratos propios elegibles del período. No incluye el padrón histórico importado por una conversión implícita. Repartición corresponde a `sector_source_id`, como en el formulario de alta publicado. Búsquedas y páginas no forman parte del comando. La población exige identidad propia y vigencia laboral continua durante el mes completo. Una vigencia parcial bloquea el conjunto sin inventar prorrateo. Una inscripción posterior al mes o una rectificación posterior/al interior del mes impide asumir un encuadre histórico. Esta restricción necesita fuentes históricas verificadas antes de habilitar esos casos.

La transacción toma bloqueos de lectura sobre las fuentes, conserva los bloqueos existentes y rechaza conflictos sin esperar indefinidamente. Captura catálogo y programa aprobados, población propia y todas las novedades mensuales aprobadas correspondientes a los contratos/período/tipo. Usa la fachada mensual v2 existente y no divide lotes mixtos. Para las fijas, reutiliza los lectores de registros e identidad092/093, con el alcance propio expreso; conserva cada declaración aprobada aplicable y su token de ámbito. Un registro de otro contrato no bloquea la selección. Identidad actual, período y vigencia se verifican; la valoración exacta usa el adaptador existente. No se modifican los exportadores publicados ni el límite500 del importador o registro de fijas.

La captura conserva cuerpo, clave, programa, fuentes e inventario con SHA256. El servidor calcula con el motor exacto y guarda entrada, resultado y sus hashes en otra tabla privada. Ambas tablas rechazan modificación, borrado y truncado; el runtime sólo ejecuta cuatro fachadas. Hay límites completos de población, fuentes, tamaño y capacidad; no se entrega un resultado recortado. Los metadatos no contienen UUID de empleados, nombres ni importes. Recuperar fuentes/resultados exige permiso nominal vigente y la misma identidad/membresía de origen.

La clave repetida recupera la misma captura antes de volver a consultar versiones actuales. Una captura pendiente no se calcula con una versión diferente del motor. Una corrida con resultado ya guardado se devuelve tal como quedó, sin recalcularla con nuevas fuentes ni otro motor. La API nunca acepta un resultado financiero enviado por el cliente. Un resultado distinto para la misma captura se rechaza. Las banderas siguen siendo `municipalApprovalVerified:false`, `payrollPosted:false` y `paymentExecuted:false`.

La recuperación completa de esta API se limita a4MiB, por debajo del [máximo de4,5MB de Vercel Functions](https://vercel.com/docs/functions/limitations). La base comprueba captura+entrada+resultado antes de insertar el resultado, con margen para el sobre HTTP; el servidor verifica también la respuesta real. Si el resultado no cabe, se conserva la captura recuperable y no se guarda ni devuelve una nómina parcial. Los límites mayores del motor reusable no garantizan transporte por esta API.

La prueba SQL ejecuta123 con las648 comprobaciones anteriores y agrega34: alta real067, programa propio aprobado122, novedad fija real092 aprobada, captura completa, hashes, sesión, permisos, reintentos, límite HTTP antes de guardar, conservación tras cambiar un parámetro salarial por la fachada112 y resultado inmutable. JavaScript prepara y calcula nuevamente desde la captura obtenida de PostgreSQL y exige coincidencia completa de entrada, filas, totales y hashes. Las tasas y códigos de QA son inventados. La transacción termina enROLLBACK. El navegador valida el recibo real sintético y la ejecución del mismo motor; no prueba una pantalla de producto.
