# C2 · guardado durable y recuperación del cálculo propio

Continuación de [novedades mensuales propias](MOTOR_PROPIO_C2_NOVEDADES_MENSUALES_20261005.md). Prueba local sintética de las fachadas existentes 122/123 y del handler HTTP real. No acredita publicación, autenticación municipal completa, aprobación normativa, contabilización ni pago.

## Circuito comprobado

Una fundación separada instala los escritores publicados y sus controles originales en un esquema sintético de la base PostgreSQL de QA existente. Conserva con COMMIT un padrón propio, encuadre/catálogo/programa aprobados por personas independientes y dos novedades mensuales aprobadas. No fabrica una captura ni un resultado inicial. El empleado del cálculo no existe en GRH.

La solicitud pasa como bytes por HTTP local, el lector JSON privado, el handler de corrida y el adaptador/motor reales. PostgreSQL vuelve a comprobar sesión, membresía, binding, versión de release y persona vinculada. Cada consulta usa un proceso/conexión psql distinto y COMMIT explícito: captura y resultado se guardan desde conexiones diferentes; otra conexión recupera entrada, seis filas, totales, hashes y fechas originales. Se usa la huella real de los archivos del motor, sin sustituirla por un valor de fixture.

La prueba simula pérdida de respuesta **después** del COMMIT de captura o resultado. La API informa incertidumbre; GET recupera sin calcular y el mismo POST/cuerpo/clave completa o devuelve lo ya guardado, sin duplicar. Una conexión independiente mantiene el lock real de ámbito: otra solicitud recibe 409 y se completa después de liberarlo. Dos solicitudes simultáneas con la misma clave convergen en una sola captura y un solo resultado. Un UPDATE del resultado falla por inmutabilidad y la lectura posterior conserva el valor original.

Chrome usa el handler/SQL reales para guardar, reintentar y comprobar que la revocación nominal en la base impide recuperar datos, incluso con un principal HTTP de QA que todavía enumera la capacidad antigua. El gateway de autenticación HTTP y el resolvedor IAM/SoD son fixtures declarados; esta prueba no suplanta a Noelia ni certifica su sesión municipal. El navegador prueba transporte y recuperación, no la UI de producto.

## Conservación y límites

Los generadores anteriores mantienen sus regresiones, restauraciones y ROLLBACK. Se extrae por separado su fundación sintética reutilizable; ninguna assertion se elimina ni se transforma una regresión en una instalación durable. La nueva fundación tiene guardas contra destino productivo y usa sólo la base local de QA existente. La limpieza elimina únicamente su esquema aleatorio verificado y se comprueba al final.

No cambia la aplicación, los escritores 122/123, los permisos municipales o las dependencias compartidas. No se instalan reglas sintéticas en producción. En Windows el transporte de QA envía SQL como bytes UTF-8 por stdin para preservar las tildes y evitar la conversión de la línea de comandos a otra página de códigos. No se cambia la codificación global del sistema.

Resultados ejecutados, hashes, archivos y pendientes en `verification/CODEX_OWN_DURABLE_RESULT_20261005.md`. Continúan pendientes la pantalla operativa de programa/corrida, las reglas municipales homologadas, auditoría/instalación 122/123 y publicación. Después siguen versiones, anulación/confirmación/cierre y recibos/planillas/informes propios; los demás módulos, actores y relojes conservan el alcance del [plan](PLAN_CIERRES_MUNICONTROL_20260930.md).
