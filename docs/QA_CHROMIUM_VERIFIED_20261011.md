# Chromium de verificación fijado por el proyecto

Los controles de fórmulas, ART, datos fiscales y preparación F.931 conservan Playwright 1.63, fixtures, aserciones, límites y permisos originales. Sus workflows usan Google Chrome for Testing 157.0.8098.0 únicamente en el checkout de QA. Versión, revisión fuente y hashes del ZIP y ejecutable Windows/Linux están fijados en `scripts/lib/patched-chromium-diagnostic-manifest.mjs`; no se sigue un canal móvil ni se modifica la junction compartida o el navegador del operador. Los workflows ajenos a este cambio conservan su configuración anterior.

Motivo: el Chromium anterior puede entregar todos los bytes de una respuesta privada `no-store` y registrar su cierre como cancelación. La [incidencia Playwright #42742](https://github.com/microsoft/playwright/issues/42742) y el [parche Chromium 8508456](https://chromium-review.googlesource.com/c/chromium/src/+/8508456) describen la reentrancia de `DelegatingBytesConsumer`. El parche registra el estado terminal antes de notificar al consumidor. Los SDK estable 1.64 y alpha 1.65 examinados todavía incluyen revisiones anteriores al parche; no constituyen una corrección.

La reproducción mantiene el lector publicado intacto y coordina dos fragmentos y EOF sin sleeps. El navegador anterior falla tres entregas completas, mientras conserva los rechazos de JSON truncado, exceso de 64 KiB y aborto explícito. El build fijado contiene el parche en su fuente declarada. En Windows pasan nueve controles, 240 solicitudes y los cinco recorridos originales; en Ubuntu pasan los nueve controles, 240 solicitudes y dieciséis ejecuciones de esos cinco recorridos, con el mismo SDK. La comparación Ubuntu está conservada en el run 38142211169, job 114478217038 del PR #172. Los fallos anteriores permanecen íntegros; no se rerunearon para obtener verde.

Instalación explícita: `node scripts/install-project-chromium.mjs --purpose=release-verification`. El preload `scripts/lib/project-chromium.mjs` comprueba versión del SDK, propósito, plataforma, revisión y hash del binario. Sólo agrega `executablePath` a la llamada original; rechaza un `channel` o ejecutable alternativo. No agrega flags ni cambia requests, rutas, caching, tiempos, cuentas, datos o aserciones. Las dependencias del sistema ya instaladas por Playwright se conservan.

El instalador de diagnóstico y su preload siguen separados; una instalación marcada como diagnóstico no satisface la admisión de release. Ambas instalaciones se guardan dentro de `verification/` y no sobrescriben una instalación existente. Ningún binario ni resultado privado se publica como parte de la aplicación.

La versión elegida es un build previo a estable de Google y está fijada exactamente. Cuando Playwright publique una revisión estable que incorpore el mismo arreglo, sustituir este runtime sólo después de repetir la reproducción, los negativos y los recorridos completos. No cambiar a una versión por su número solamente.

Este cambio corrige la infraestructura de QA. No acredita aceptación de Noelia, una sesión real, homologación salarial/fiscal, adopción del padrón o autonomía integral. Una denegación de Computer Use no se reintenta ni se sustituye mediante este runtime; los recorridos son sintéticos y locales/CI.
